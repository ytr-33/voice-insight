# 起草・修正フェーズ

文書構成計画とテンプレートに従い、要件定義書から基本設計書を作成する。

## 手順

1. `references/template.md` を読む。
2. 文書構成計画がある場合は、そのファイル構成とID接頭辞に従う。ない場合は `documents/20_基本設計/基本設計書.md` を既定にする。
3. 要件IDを維持し、設計IDを追加する。
4. 設計判断には、採用理由、不採用案、関連要件、影響を付ける。
5. 仮定ログは前提・仮定へ転記する。
6. 未回答の質問は未決事項へ残し、関連設計に未決であることを示す。
7. レビュー指摘を受けた場合は、指摘された箇所だけを修正する。

## 厳守

- 要件定義にない機能を追加しない。
- 保存しない、ユーザー管理しない、対象外といった制約を便利さで崩さない。
- 詳細設計や実装コードを書かない。
- 未決事項を隠すために設計を確定させない。
