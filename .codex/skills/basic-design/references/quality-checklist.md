# 基本設計書の品質チェックリスト

完成ドラフトを採点し、重大度付きで指摘する。レビュー時は本文を書き換えず、問題と修正方針を返す。

## 個別設計のチェック

- [ ] 設計IDがあり、ファイルをまたいで一意か。
- [ ] 関連する要件IDへ辿れるか。
- [ ] 設計判断の根拠が書かれているか。
- [ ] 採用案だけでなく、重要な不採用案または代替案の扱いが分かるか。
- [ ] 曖昧語だけで終わらず、検証可能な条件や目標値があるか。
- [ ] 基本設計の粒度を超えた実装詳細を書きすぎていないか。

## 文書全体のチェック

- [ ] スコープと対象外が要件定義と矛盾しないか。
- [ ] 要件IDとのトレーサビリティ表があり、未対応要件がないか。
- [ ] 画面、API、データ、処理、非機能の用語や状態名が一致しているか。
- [ ] データを保存しない要件がある場合、永続化、ログ、外部送信、一時保持の扱いが矛盾していないか。
- [ ] 外部AIや外部サービスを使う場合、送信データ、失敗時、タイムアウト、ユーザー影響が書かれているか。
- [ ] エラー時の復帰導線が画面設計と処理設計で一致しているか。
- [ ] 非機能要件の性能、セキュリティ、可用性、運用、法令が抜けていないか。
- [ ] 前提・仮定・未決事項が集約され、本文に隠れた仮定が紛れていないか。
- [ ] 後続工程へ送る事項が、基本設計で決めるべき事項の先送りになっていないか。

## 重大度

- 致命: 要件と矛盾する、未対応要件がある、ステークホルダー判断を捏造している、データ保存や外部送信の方針が要件に反する。
- 重要: 後工程で大きな手戻りを起こす。例: 技術選定の根拠不足、外部連携エラー未設計、非機能目標の未定義。
- 軽微: 表記ゆれ、章立て、説明不足など、設計成立を直接妨げない問題。

## 出力フォーマット

```
## レビュー結果サマリ
- 致命: N件 / 重要: N件 / 軽微: N件
- 判定: [合格 / 不合格]

## 指摘一覧
- [致命] 対象: <章 or 設計ID> / 内容: <問題> / 修正方針: <どう直すか>
- [重要] 対象: ... / 内容: ... / 修正方針: ...
- [軽微] 対象: ... / 内容: ... / 修正方針: ...

## 未対応要件
- <要件ID>: <未対応内容>

## 残す場合に未決事項へ移すべき指摘
- <指摘>: <理由>
```

## 合格基準

致命が0件なら合格。重要指摘が残る場合は、未決事項または後続工程への申し送りとして明示されていることを確認する。
