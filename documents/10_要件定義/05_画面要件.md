# 05 画面要件

Phase1で必要な画面と、各画面が満たすべき要件を定義する。詳細なUIデザイン・レイアウトは後続の設計工程に委ね、本書では画面の役割・要素・状態を要件レベルで示す。

Phase1はユーザー管理・データ保存を行わないため、画面は単一の流れ（録音→処理→結果）で完結する。

## 5.1 画面遷移

```
[録音画面]
   │ 録音開始 → 録音中 → 録音停止
   ▼
[処理中画面]（文字起こし・評価を自動実行）
   │ 成功
   ▼
[評価結果画面]
   │ 「もう一度」 → 録音画面へ戻る

※ 各段階で失敗した場合は [エラー表示] を出し、録音画面へ戻る導線を示す。
```

## 5.2 画面・状態の要件

### S-01 録音画面

- 録音開始の操作ができること。
- 録音中であることが分かること（状態表示）。
- 録音中は停止の操作ができること。
- 最大録音時間（5分）に達した場合の扱いが分かること。
- マイク利用が許可されていない場合、録音を開始できない理由を表示すること。

状態: 録音前 / 録音中 / マイク不許可。

### S-02 処理中画面

- 文字起こし・評価が処理中であることが分かること。
- ユーザーの追加操作なしで処理が進むこと。

状態: 文字起こし中 / 評価中（まとめて「処理中」として表現してもよい）。

### S-03 評価結果画面

[F-04 評価結果表示](03_機能要件.md) の項目を表示する。

- 総合点
- PREP観点の評価
- 良い点
- 改善点
- 次回話すときの具体的な改善提案
- もう一度録音し直す導線

### S-04 エラー表示

- 録音・文字起こし・評価のいずれかに失敗した場合、再録音できる導線を表示すること。
- マイク不許可の場合は、その理由を表示すること（S-01に内包）。

## 5.3 プライバシーに関する画面表示

- 音声・文字起こし・評価結果を保存しない前提を、ユーザーに分かるように画面上で示す。
- 外部AIサービスを利用する場合は、音声や文字起こしが外部サービスに送信される可能性を明示する。

（詳細は [06_非機能要件](06_非機能要件.md) のプライバシー項を参照）
