## 1. 背景・目的

### 1.1 背景

発表・商談・面接などの場面では「話の分かりやすさ」が成果を左右する。しかし、自分の話し方を客観的に振り返る手段は限られている。録画・録音した内容を自分で聞き直しても、構成上の良し悪しを言語化することは難しい。

Voice Insight は、ブラウザ上でユーザーが一人で話した内容を AI で分析し、話し方の改善につなげる音声分析 Web アプリケーションである。本書は、その初期リリース範囲である Phase1 の要件を定義する。

### 1.2 目的（ビジネスゴール）

| ゴールID | ビジネスゴール |
| --- | --- |
| G-01 | ユーザーが一人で手軽に話す練習を行い、話の構成について客観的なフィードバックを得られるようにする。 |
| G-02 | フィードバックを次回の練習でそのまま意識できる、具体的な改善提案の形で提供する。 |

「なぜ作るのか」: ユーザーが自力では言語化しにくい「話の構成の分かりやすさ」を、AI による客観的な評価と具体的な改善提案として返すことで、一人での反復練習による話し方改善を支援するため。

### 1.3 Phase 構成

- **Phase1（本書の対象）**: 話した内容の「構成」を PREP（Point → Reason → Example → Point）観点で評価する。音声特徴（息継ぎ・速さ・トーン）の分析は行わない。利用シーン別に評価基準を切り替えない。
- **Phase2 以降（本書の対象外）**: 音声特徴に基づく分析を追加する将来範囲。追加候補は「息継ぎの多さ」「声の速さ」「声のトーン」。分析方式・利用技術・評価基準・表示方法は後続工程で検討する。

## 2. スコープ

### 2.1 対象範囲（Phase1）

- ブラウザ上での音声録音（最大 5 分）
- 録音音声の AI 文字起こし（日本語のみ）
- 文字起こし結果をもとにした AI 構成評価（PREP 観点）
- 評価結果の画面表示（総合点・PREP 観点の評価・良い点・改善点・具体的な改善提案）
- 単一の流れ（録音画面 → 処理中画面 → 評価結果画面）と、各段階の失敗時に録音画面へ戻す導線

### 2.2 対象外（Phase1）

以下は Phase1 では「あえて扱わない」。後続の合意なしに実装してはならない。

| 対象外項目 | 理由 |
| --- | --- |
| ユーザー登録・ログイン・アカウント管理 | 気軽に何度も練習できることを優先し、ユーザー管理を持たない（NF-03）。 |
| 録音音声・文字起こし結果・評価結果の保存（永続化） | データを一切永続化しない方針（NF-03）。 |
| 評価履歴の表示・過去結果との比較 | 保存しないため履歴を持たない（NF-03 / 8章リスク）。 |
| 文字起こし結果の確認画面・編集機能 | 停止後は追加操作なしで自動進行する設計のため（F-02 / UC-01）。 |
| 利用シーン別（発表・商談・面接）の評価基準切り替え | Phase1 は共通の PREP 評価のみ（1.3 / 5章 業務要件）。 |
| 複数人会話の分析 | Phase1 は一人での発話のみ対象。 |
| リアルタイム（発話中の逐次）評価 | Phase1 は録音停止後のバッチ的な評価のみ。 |
| 管理者向け機能 | Phase1 の利用者は練習者のみ（3章）。 |
| 音声特徴（息継ぎ・声の速さ・声のトーン）の分析 | Phase2 以降の将来要件。 |
| プライバシーに関する画面表示・同意取得 | ステークホルダー判断 D2 により撤廃（8章 / 10章 ISS-05）。データ非永続化の挙動（NF-03）は維持する。 |

## 5. 業務要件 / 主要ユースケース

### 5.1 想定ユーザー

- 発表・商談・面接などで、自分の話し方を改善したい個人。
- 話の構成が分かりやすいかを客観的に確認したい個人。
- 短いスピーチや回答を繰り返し練習したい個人。

### 5.2 利用シーン

Phase1 では特定の業務・場面に限定せず、発表練習・商談練習・面接練習の用途で共通して利用できることを前提とする。ただし利用シーン別に評価基準を切り替えず、すべてのシーンに共通する基本的な話の構成（特に PREP に基づく分かりやすさ）を評価する。

### 5.3 主要ユースケース

#### UC-01 話の構成を評価してもらう（基本フロー）

1. ユーザーがアプリを開く（録音画面 S-01 を表示）。
2. ユーザーがマイク利用を許可し、録音を開始する。
3. ユーザーが伝えたい内容を話す（最大 5 分）。
4. ユーザーが録音を停止する。**または、録音時間が 5 分に達した時点でシステムが自動停止する（D1）。**
5. システムが、ユーザーの追加操作なしで文字起こしと構成評価を実行する（処理中画面 S-02 を表示）。
6. ユーザーが評価結果（総合点・PREP 観点の評価・良い点・改善点・改善提案）を確認する（評価結果画面 S-03）。
7. ユーザーが改善点を踏まえ、「もう一度」導線から再度録音をやり直す。

#### 代替・例外フロー

- **EX-01 マイク不許可**: マイク利用が許可されない場合、録音を開始できない理由を表示する（S-01 / NF-06）。
- **EX-02 処理失敗**: 録音・文字起こし・評価のいずれかに失敗した場合、再録音できる導線を表示する（S-04 / NF-06）。外部 AI サービスの応答遅延・タイムアウト（規定時間内に応答が返らない）も失敗として扱い、再録音導線を出す。タイムアウト値自体は設計工程で定義する。

### 5.4 ユーザーストーリー

- 練習者として、話し終えたらすぐに構成のフィードバックを受け取りたい。確認や編集の手間なく結果を見たいからだ。
- 練習者として、何が良くて何を直すべきかを具体的に知りたい。次の練習でそのまま意識したいからだ。
- 練習者として、登録やログインなしで使い始めたい。気軽に何度も練習したいからだ。

## 6. 機能・画面要件

各機能要件には一意な ID（既存 `F-xx` を踏襲）・MoSCoW 優先度・受け入れ基準を付与する。評価の中身（PREP 観点・出力項目）の詳細は 6.5 に、画面・状態要件（S-xx）は 6.6 にまとめる。

### 機能一覧

| ID | 機能 | 概要 | 優先度 |
| --- | --- | --- | --- |
| F-01 | 録音 | ブラウザ上での音声録音（最大 5 分、5 分到達で自動停止） | Must |
| F-02 | AI 文字起こし | 録音音声の文字起こし（日本語のみ、確認・編集なし） | Must |
| F-03 | AI 構成評価 | 文字起こし結果の PREP 構成評価 | Must |
| F-04 | 評価結果表示 | 評価結果の画面表示 | Must |

### 6.1 F-01 録音

| 項目 | 内容 |
| --- | --- |
| 優先度 | Must |
| 要件 | ユーザーはブラウザ上で録音を開始・停止でき、1 回の録音は最大 5 分とする。録音中は録音中であることを画面に表示する。録音時間が 5 分に達した場合はシステムが自動停止する（D1）。録音停止後（手動停止・自動停止のいずれも）、ユーザーの追加操作なしで文字起こし・評価処理へ進む。 |
| 関連 | UC-01, S-01, S-02, NF-01, NF-05 |

受け入れ基準:
- AC-F01-1: ユーザーがブラウザ上で録音を開始・停止できる。
- AC-F01-2: 録音中であることが画面上の状態表示で識別できる。
- AC-F01-3: 録音時間が 5 分に達すると、ユーザー操作なしで録音が自動停止する（D1）。
- AC-F01-4: 手動停止・自動停止のいずれの場合も、確認画面を挟まず追加操作なしで処理中画面（S-02）へ遷移する。
- AC-F01-5: 1 回の録音時間が 5 分を超えられない（録音上限が 5 分に制限され、5 分到達で録音を継続できず自動停止する）。本基準が「録音上限 5 分」の正本であり、Must 制約（8.1 / D1）の検証点とする。AC-NF05-1 はこの再掲（従）である。

### 6.2 F-02 AI 文字起こし

| 項目 | 内容 |
| --- | --- |
| 優先度 | Must |
| 要件 | 録音された音声を AI で文字起こしする。Phase1 の対象言語は日本語のみとする。文字起こし結果は構成評価（F-03）の入力としてのみ利用し、ユーザー向けの確認画面・編集機能は提供しない。 |
| 関連 | UC-01, F-03, NF-02, NF-06 |

受け入れ基準:
- AC-F02-1: 録音停止後、AI による日本語の文字起こしが実行される。
- AC-F02-2: 文字起こし結果がそのまま F-03 の入力として渡る（ユーザーによる確認・編集の画面が存在しない）。
- AC-F02-3: 文字起こしに失敗した場合、再録音できる導線（S-04）が表示される。

### 6.3 F-03 AI 構成評価

| 項目 | 内容 |
| --- | --- |
| 優先度 | Must |
| 要件 | AI は文字起こし結果をもとに、PREP を重視して話の構成を評価する。評価結果は、総合点・PREP 観点の評価・良い点・改善点・改善提案をすべて含む形式とする（評価観点・出力項目は 6.5。点数の値・スケールは設計委ね D4 / AS3）。評価処理中であることを画面に表示する。評価に失敗した場合、再録音できる導線を表示する。 |
| 関連 | UC-01, F-04, S-02, S-04, NF-05, NF-06 |

受け入れ基準:
- AC-F03-1: AI が文字起こし結果をもとに PREP を重視した構成評価を返す。
- AC-F03-2: 評価結果に、総合点・PREP 観点の評価・良い点・改善点・改善提案がすべて含まれる（F-04 の表示項目 AC-F04-1 と一致）。なお、総合点の値・スケール・算出基準は設計工程に委ねる（D4 / AS3）。本基準が検証するのは「どの項目を出力するか」であり、点数の値そのものではない。
- AC-F03-3: 評価処理中であることが画面上で識別できる。
- AC-F03-4: 評価に失敗した場合、再録音できる導線（S-04）が表示される。

### 6.4 F-04 評価結果表示

| 項目 | 内容 |
| --- | --- |
| 優先度 | Must |
| 要件 | 評価結果画面に、少なくとも次の項目を表示する: 総合点 / PREP 観点の評価 / 良い点 / 改善点 / 次回話すときの具体的な改善提案。評価結果は保存しないため、画面を離れた後に同じ評価結果を再表示できることは要件に含めない。 |
| 関連 | UC-01, S-03, NF-03 |

受け入れ基準:
- AC-F04-1: 評価結果画面に総合点・PREP 観点の評価・良い点・改善点・具体的な改善提案がすべて表示される。
- AC-F04-2: 改善提案は「次回話す際にそのまま意識できる」具体的な表現で示される。
- AC-F04-3: 評価結果画面から「もう一度」録音し直す導線が利用できる。

### 6.5 評価の中身（F-03 / F-04 の詳細）

#### 6.5.1 評価方針

Phase1 の評価対象は、声質や話し方そのものではなく、文字起こしされた発話内容の構成である。話が聞き手に伝わりやすい構造になっているかを確認し、特に PREP（Point / Reason / Example / Point）を重視して、主張・理由・具体例・結論の流れが自然かを評価する。

#### 6.5.2 評価観点

AI は以下の観点で評価する。

- 主張が明確か。
- 理由が主張を支えているか。
- 具体例が含まれているか。
- 最後に要点や結論へ戻れているか。
- 話全体の流れが自然か。
- 聞き手にとって理解しやすい順序になっているか。

#### 6.5.3 評価結果の出力項目（F-04 で表示）

| 項目 | 内容 |
| --- | --- |
| 点数（総合点） | 話の構成の分かりやすさを表す指標として表示する。スケール・算出基準・表示意図は設計工程で確定する（D4 / AS3）。 |
| PREP 観点の評価 | 6.5.2 の観点に沿った評価を示す。 |
| 良い点 | ユーザーが維持すべき要素として提示する。 |
| 改善点 | 次に直すべき構成上の課題として提示する。 |
| 改善提案 | 次回話す際にそのまま意識できる具体的な表現にする。 |

#### 6.5.4 留意事項

- AI による評価は一貫性に揺れが出る可能性があるため、評価プロンプト・出力フォーマットの具体は設計工程で定義する（AS5 / 8章）。
- 点数の算出基準・スケールは設計工程で確定する。本書では「構成の分かりやすさを表す指標を表示する」ことのみを要件とする（D4）。

### 6.6 画面・状態要件

詳細な UI デザイン・レイアウトは設計工程に委ね、本書では画面の役割・要素・状態を要件レベルで示す。Phase1 はユーザー管理・データ保存を行わないため、画面は単一の流れ（録音 → 処理 → 結果）で完結する。

#### 画面遷移

```
[録音画面 S-01]
   │ 録音開始 → 録音中 → 録音停止（手動）または 5分到達で自動停止（D1）
   ▼
[処理中画面 S-02]（文字起こし・評価を自動実行）
   │ 成功
   ▼
[評価結果画面 S-03]
   │ 「もう一度」 → 録音画面へ戻る

※ 各段階で失敗した場合は [エラー表示 S-04] を出し、録音画面へ戻る導線を示す。
```

| ID | 画面 | 要件 | 状態 |

## 8. 制約条件

### 8.1 確定済みの制約（Phase1 で逸脱不可）

- データを一切永続化しない（NF-03）。録音音声・文字起こし結果・評価結果のいずれも保存しない。
- ユーザー管理（登録・ログイン・履歴）を作らない（NF-03）。
- 日本語のみ対象（NF-02）。
- 録音は最大 5 分。5 分到達で自動停止する（F-01 / D1）。
- 録音停止後は確認画面を挟まず、追加操作なしで文字起こし → 評価へ自動進行する。文字起こし結果の確認・編集画面は作らない（F-02 / UC-01）。
- PC ブラウザが主対象。スマホ対応は Phase1 で必須としない（NF-01）。
- エラー時（マイク不許可・録音/文字起こし/評価失敗）は必ず再録音導線を出す（NF-06）。
- 評価結果画面には最低限、総合点 / PREP 観点の評価 / 良い点 / 改善点 / 次回への具体的な改善提案を表示する（F-04）。
- 利用シーン別の評価基準切り替えは持たない（1.3 / 5.2）。

### 8.2 リスク

- Phase1 では文字起こし結果を編集できないため、AI 文字起こしの誤りが構成評価に影響する可能性がある。
- Phase1 では評価結果を保存しないため、過去結果との比較や成長の可視化はできない。
- Phase1 では利用シーン別の評価基準を持たないため、発表・商談・面接それぞれに特化した詳細評価はできない。
- Phase1 では音声特徴を分析しないため、話す速さ・声のトーン・息継ぎに関するフィードバックはできない。
- AI による評価は一貫性に揺れが出る可能性があるため、設計工程で評価プロンプト・出力形式を定義する必要がある。
- D2 によりプライバシー表示を撤廃したことで、外部 AI サービスへの送信に関するユーザー周知が画面上で行われない。法令・規程適合の要否は要確認（10章 ISS-05）。

### 8.3 設計工程に委ねる事項（本書では固定しない）

- フロントエンド/バックエンドの技術スタック。
- 利用する文字起こし・評価の AI モデルおよびサービス。
- 音声データの一時的な取り回し方法（保存しない前提でのメモリ・通信の扱い）。
- ホスティング・デプロイ方式、限定公開の具体的なアクセス制限方式。
- 評価プロンプト・出力フォーマット、点数のスケール・算出基準・表示意図（D4）。
- 応答時間などの性能目標値。

### 8.4 予算・期日

リリース期日・予算・外部 AI API の従量課金コスト上限は未確定（10章 ISS-02）。

## 11. トレーサビリティ

### 11.1 機能要件 → ビジネスゴール

各機能要件が 1.2 のビジネスゴール（G-01: 客観的な構成フィードバックを得る / G-02: そのまま意識できる具体的改善提案）にどう紐づくかを示す。どのゴールにも紐づかない要件（＝過剰）がないことの検証に用いる。

| 機能要件 | G-01（客観的な構成フィードバックを得る） | G-02（そのまま意識できる具体的改善提案） |
| --- | --- | --- |
| F-01 録音 | ○ 評価対象となる発話を取得する起点。 | ○ 反復練習の入口（「もう一度」で再録音）。 |
| F-02 AI 文字起こし | ○ 客観評価の入力（テキスト化）を生成。 | △ 改善提案の前提データを供給。 |
| F-03 AI 構成評価 | ○ PREP 観点での客観的な構成評価を生成。 | ○ 改善点・改善提案を生成。 |
| F-04 評価結果表示 | ○ 総合点・PREP 評価・良い点をユーザーに提示。 | ○ 次回そのまま意識できる改善提案を提示。 |

凡例: ○=直接寄与 / △=間接寄与。すべての機能要件が G-01 または G-02 に紐づいており、過剰要件は存在しない。
