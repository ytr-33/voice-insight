# ログ設計

## 1. 概要

`backend/main.py` における分析処理（文字起こし・PREP評価）のデバック用のログ設計を定義する。  
デバッグおよび障害調査を目的とし、ユーザーの音声内容と評価結果をサーバーサイドで記録する。

---

## 2. ロガー設定

| 項目 | 値 |
|------|----|
| ロガー名 | `voice_insight` |
| ログレベル | `DEBUG` |
| ハンドラー | `RotatingFileHandler` |
| 出力先ファイル | `backend/logs/analysis.log` |
| ローテーション上限 | 5 MB / ファイル |
| バックアップ世代数 | 3 世代（`analysis.log.1` ～ `.3`） |
| エンコーディング | UTF-8 |

**フォーマット:**

```
%(asctime)s %(message)s
```

**タイムスタンプ形式:**

```
YYYY-MM-DD HH:MM:SS
```

出力例:

```
2026-06-23 08:01:26 [91d71750] ========== ANALYSIS ==========
```

---

## 3. リクエスト識別子

各 `/api/analyze` リクエスト受信時に `uuid.uuid4().hex[:8]`（8桁の16進数）を生成し、  
そのリクエストに属する全ログ行の先頭に `[req_id]` として付与する。  
複数リクエストが混在するログファイルでも、リクエスト単位のフィルタリングを可能にする。

---

## 4. ログ種別と出力タイミング

### 4-1. INFOログ — 分析結果（正常系）

`_log_analysis()` 関数が文字起こし・PREP評価の完了後に出力する。  
1リクエストにつき以下の構造で複数行を出力する。

```
[req_id] ========== ANALYSIS ==========
[req_id] [TRANSCRIPTION]
[req_id] <文字起こし全文>
[req_id] [PREP BREAKDOWN]
[req_id] Point     score=<0-25>/25  quote=<発話引用>
[req_id] Reason    score=<0-25>/25  quote=<発話引用>
[req_id] Example   score=<0-25>/25  quote=<発話引用>
[req_id] Conclude  score=<0-25>/25  quote=<発話引用>
[req_id] [TOTAL] score=<0-100>/100  <総合コメント>
```

各 `quote` フィールドは GPT-4o が抽出した発話の該当箇所をそのまま記録する。  
PREP要素に該当する発話がない場合は `（該当なし）` と記録する。

### 4-2. WARNINGログ — 文字起こし結果が空

文字起こし成功後、テキストが空文字だった場合に出力する。

```
[req_id] 文字起こし結果が空
```

その後 HTTP 422 を返してリクエストを終了する。

### 4-3. ERRORログ — 外部API呼び出し失敗

文字起こし（OpenAI Whisper）または PREP評価（GPT-4o）の呼び出しで例外が発生した場合に出力する。

```
[req_id] 文字起こし失敗: <例外メッセージ>
[req_id] 構成評価失敗: <例外メッセージ>
```

その後 HTTP 502 を返してリクエストを終了する。

---

## 6. プライバシー上の注意

ログには発話の文字起こし全文が平文で記録される。  
要件 NF-03（データ永続化なし）の趣旨に照らし、運用上は以下を守ること:

- ログファイルをバージョン管理（Git）に含めない（`.gitignore` で除外済み）。
- 本番環境では適切なアクセス制御（ファイルパーミッション等）をかける。
- 不要になったログは速やかに削除する。
