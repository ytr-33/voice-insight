# 品質チェックリスト(レビュー役)

完成ドラフトを以下で採点する。新しい文章は書かず、評価と指摘に徹する。

## 個々の要件のチェック
- [ ] 一意: ID があり重複していない
- [ ] 明確: 曖昧語(「適切に」「迅速に」「など」「柔軟に」)が無い/定量化されている
- [ ] 検証可能: 受け入れ基準が書け、満たしたか確認できる
- [ ] 実現可能: 制約の範囲で実現できそう
- [ ] 必要: トレーサビリティ表でビジネスゴールに辿れる(辿れない＝過剰の疑い)
- [ ] 一貫: 他要件と矛盾しない

## 文書全体のチェック
- [ ] スコープの「対象外」が明記されている
- [ ] 非機能の主要カテゴリ(性能/可用性/セキュリティ/運用/法令 等)に穴がない、
      または「対象外」と明示されている。**目標値が定量か**
- [ ] 「前提条件・仮定」章があり、仮定ログが転記されている(隠れた仮定が本文に紛れていないか)
- [ ] 「未決事項」が放置・誤魔化されていない。要件の捏造で穴を塞いでいないか
- [ ] 用語が定義され、解釈ブレが無い

## 指摘の出力フォーマット(必ずこの形で返す)

重大度を3段階で付与する。
- **致命**: これがあると要件として成立しない(矛盾、検証不能、捏造された前提 等)
- **重要**: 後工程で手戻りを起こす(非機能の欠落、曖昧な定量目標 等)
- **軽微**: 体裁・表現レベル

```
## レビュー結果サマリ
- 致命: N件 / 重要: N件 / 軽微: N件
- 判定: [合格 / 不合格]   ← 致命が0件なら「合格」

## 指摘一覧
- [致命] 対象: <章 or 要件ID> / 内容: <何が問題か> / 修正案: <どう直すか>
- [重要] 対象: ... / 内容: ... / 修正案: ...
- [軽微] 対象: ... / 内容: ... / 修正案: ...
```

## 合格基準
**致命=0件で「合格」**。重要が残っていても合格にできるが、その場合は
残った重要指摘を未決事項として明記させること(司令塔が判断する)。
