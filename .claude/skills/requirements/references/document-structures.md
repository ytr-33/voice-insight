# 要件定義書の分割パターン(構成カタログ)

1ファイルだと全体を浅く書きがち。規模に応じて分割する。設計役がここから選び、作成役がこの割り方に従う。
**横断ドキュメント(非機能・用語・制約・トレーサビリティ)は重複を避けるため原則1ファイルに集約**する。

## 規模の見極め

- **小規模**(単機能・PoC・社内ツール): 無理に割らない。1ファイル(`template.md` の章立て)で十分。
- **中規模**(標準的な業務システム): 4〜6ファイルに分ける。下記「中規模セット」。
- **大規模**(複数サブシステム/多数の機能ドメイン): 機能要件をドメイン単位で分割。下記「大規模セット」。

## 中規模セット

| ファイル | 目的 | 含む章(template.md 準拠) | ID接頭辞 |
| --- | --- | --- | --- |
| `00-overview.md` | 背景・目的・スコープ・ステークホルダー | 0,1,2,3 | — |
| `10-functional.md` | 機能要件・主要ユースケース | 5,6 | FR- |
| `20-nonfunctional.md` | 非機能要件 | 7 | NFR- |
| `90-appendix.md` | 用語・制約・前提/仮定・未決事項・トレーサビリティ | 4,8,9,10,11 | AS-/OQ- |

## 大規模セット

機能要件をサブシステム/機能ドメインごとに分け、横断系は独立文書にする。

| ファイル | 目的 | ID接頭辞 |
| --- | --- | --- |
| `00-overview.md` | 全体像・スコープ・ステークホルダー・体制 | — |
| `10-func-<domainA>.md` | ドメインAの機能要件 | FR-A- |
| `10-func-<domainB>.md` | ドメインBの機能要件 | FR-B- |
| `20-nonfunctional.md` | 非機能要件(全ドメイン共通) | NFR- |
| `30-data.md` | データ要件・データモデル | DR- |
| `40-interface.md` | 外部インターフェース要件(連携先・API) | IF- |
| `50-migration-ops.md` | 移行要件・運用保守要件 | MG-/OP- |
| `90-appendix.md` | 用語・制約・前提/仮定・未決事項・トレーサビリティ | AS-/OQ- |

## 分割時の必須ルール

- **ID はファイルをまたいで一意**(接頭辞で衝突回避)。同じ ID を別ファイルで再利用しない。
- **トレーサビリティは集約ファイルで一元管理**。各機能要件 → ビジネスゴールの対応を1か所で見られるようにする。
- **前提/仮定・未決事項も集約**。各ファイルに散らさない(レビューと人間確認の効率が落ちるため)。
- **目次/索引ファイル**(`00-overview.md` 冒頭にファイル一覧と各IDレンジ)を必ず置き、迷子を防ぐ。
- ファイル間で内容を重複コピーしない。参照する場合は「`20-nonfunctional.md` の NFR-003 参照」と書く。
